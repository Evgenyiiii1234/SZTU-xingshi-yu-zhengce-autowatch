## 一、倍速伪装

### 关键事实

`playbackRate` 不是 `<video>` 元素自己身上的普通属性，而是定义在 **`HTMLMediaElement.prototype`** 上的 accessor（getter/setter）：

```js
Object.getOwnPropertyDescriptor(HTMLMediaElement.prototype, 'playbackRate')
// → { get: [Function: get playbackRate], set: [Function: set playbackRate], ... }
```

播放器想检查倍速，只能走这两个入口之一：读 `video.playbackRate`，或者监听 `ratechange` 事件。

### 做法

把原型上的这对 accessor 换掉：

```js
const desc = Object.getOwnPropertyDescriptor(HTMLMediaElement.prototype, 'playbackRate');
Object.defineProperty(HTMLMediaElement.prototype, 'playbackRate', {
  configurable: true,
  get() {
    return 1;                       // 页面永远读到 1
  },
  set(v) {
    desc.set.call(this, Math.max(8, v));   // 页面写 1，实际变成 8
  },
});
```

两个副作用都是我们想要的：

1. 播放器自己执行 `video.playbackRate = 1`（很多播放器每隔几秒纠一次速），经过我们的 setter 后反而被抬到 8×。
2. 播放器读 `video.playbackRate` 校验，拿到 `1`，一切正常。

### 顺带处理的 `defaultPlaybackRate`

有的播放器写 `defaultPlaybackRate` 再 `load()`。同样换掉 getter/setter。

### 真实倍率存在哪

`WeakMap`：

```js
const realRateSet = new WeakMap();
// setter 里： realRateSet.set(this, real);
```

因为 getter 已经被污染了，脚本自己判断“当前是不是 8×”也得查这个 Map，不能用 `video.playbackRate`。

## 二、防暂停 / 防失焦

平台判断“人不在”的常见手段，和对应处理：

| 平台手段 | 处理 |
| --- | --- |
| `document.hidden` / `visibilityState` | `Object.defineProperty` 到 `Document.prototype` 上，恒返回 `false` / `'visible'` |
| `blur` / `visibilitychange` / `pagehide` 事件 | 在 `EventTarget.prototype.addEventListener` 上做过滤：`document`/`window` 注册这些事件时直接不注册 |
| 播放器调 `video.pause()` | 监听 `pause` 事件（捕获阶段），80ms 后 `play()` 拉回 |
| `video.paused` 轮询 | 600ms 巡检一次，`paused && !ended` 就 `play()` |
| 定时 `window.dispatchEvent(new Event('focus'))` 补焦点 | 每 4 秒补发一次 |

注意 `pause` 事件不是 `addEventListener` 拦截——播放器是直接调方法，没有事件注册可拦。所以用“事件发生后立刻反向操作”的方式，代价是会有极短暂的一帧暂停状态。

## 三、进度上报录制与回放（重点）

### 为什么不能只靠加速

平台只要在服务端记一行：

```
(t1, pos1) → (t2, pos2)    如果 (pos2 - pos1) / (t2 - t1) > 1.3  → 判定异常
```

客户端怎么伪装都没用，因为它看的是自己的时钟。所以真正的解法是**让上报的曲线看起来是 1×**。

### 录制

钩 `open/send` 和 `fetch`，命中关键词的请求整条存下来：

```js
{ t, method, url, body, headers }
```

判定规则（`isReport()`）：URL 里含 `progress|study|learn|record|watch|heartbeat|video|res|stu`，或 body 里含 `position|currentTime|playTime|studyTime|duration|rate` 之类的字段。静默丢弃静态资源。

存到 `localStorage`，最多 400 条。

### 回放

1. 从录到的模板里挑出“真的像进度上报”的（body 里有位置字段，或 URL 命中进度关键词）。
2. **判别单位**：拿模板里第一个位置字段的值和视频总时长比一下，大于 `duration × 3` 就认为是毫秒。这样 `position: 12`（秒）和 `position: 12000`（毫秒）都不会改错。
3. **只改位置类字段**，其余原样：
   - 键名命中 `pos|position|currentTime|playTime|studyTime|progress|played|elapsed|seek` → 换成当前步的位置
   - 命中 `duration|total` → 换成总时长
   - 命中 `rate|speed` → 换成 `1`
   - `stuId`、`vid`、`token`、签名、`state` → **一个字不动**
4. 按 `0 → duration` 分 20 步，每步间隔 1.5 秒，串行重发。
5. `window.__DFE_REPLAY` 标志位挡住录制钩子，避免把回放请求又录一遍。

JSON 和 `application/x-www-form-urlencoded` 两种 body 都支持；`walkMutate()` 递归处理嵌套 JSON。

### 先演练

面板的「回放打点」第一次会问“先演练一次？”——输入 `y` 只打日志不发请求。看清这行：

```
[dry] POST https://.../UpdateProgress.ashx {"vid":88,"position":300,"duration":600,"rate":1,"state":1}
```

确认 `position` 变得对、`state` 没被改、`duration` 对，再输入 `n` 真发。

## 四、转写管线

```
m3u8/mp4 ──yt-dlp（内置 HLS 下载器）──▶ mp4
                                          │
                                    PyAV 解码音轨（自带 FFmpeg 库）
                                          │
                                    16 kHz 单声道 float32
                                          │
                              faster-whisper（CTranslate2, int8）
                                          │
                    ┌─────────────────────┼─────────────────────┐
                 .txt 时间戳          .srt 字幕            .md 阅读稿
```

三个“不需要”：

- **不需要 ffmpeg 可执行文件**：yt-dlp 的 `--hls-prefer-native` 用 Python 自己拉 m3u8 分片；PyAV 里打包了 FFmpeg 的库，解码不用外部程序。
- **不需要 GPU**：`compute_type="int8"` 在 CPU 上跑 `small` 大约 0.3–0.4× 实时。
- **不需要联网二次调用**：模型只在第一次下载，之后全本地。

### 为什么有 `patch_av_compat()`

PyAV 19 把 `av.open(..., metadata_errors=...)` 这个参数删了，而 faster-whisper 1.2.x 还在传，直接调用会：

```
TypeError: open() got an unexpected keyword argument 'metadata_errors'
```

`transcribe.py` 在导入 faster-whisper 之前给 `av.open` 包了一层，把多余的关键字参数吃掉：

```python
orig = av.open
def _open(*a, **kw):
    kw.pop("metadata_errors", None)
    return orig(*a, **kw)
av.open = _open
```

比锁版本更省事——PyAV 14 没有 cp313 的 wheel，锁版本会在 Python 3.13 上编译失败。

### VAD 与提示词

- `vad_filter=True`：先用 VAD 切掉静音段，课件里长时间翻 PPT 不说话的部分不会喂给模型，快很多而且减少幻觉。
- `initial_prompt`：把本课专业词写进去（`--prompt "二叉树 中序遍历"`），Whisper 会倾向用这些词，术语准确率提升明显。
- `condition_on_previous_text=False`：关掉上文条件，避免一句话错了后面整段跟着错（代价是段落连贯性略降）。

## 五、为什么 `summarize.py` 的抽取式提纲这么“土”

因为它**只做兜底**，不做文字生成。真正的成稿交给大模型，脚本负责三件事：

1. 把 75 秒一段的转写稿拼成适合喂给模型的形状；
2. 把指令写好（结构、语气、禁止事项）；
3. 打包成一个 `.md`，复制粘贴就能用。

抽取用的是「汉字词频 × 位置权重 ÷ 句子长度^0.7」，没有分词库依赖。够用来判断“这段在讲什么”，不够用来交作业——这是设计上的分工。
